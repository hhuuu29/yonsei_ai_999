# 개인 비서 + 친구에게 일정 공유 — 첫 운영 버전

2026-09-10 사용자 확정: 개인 비서와 친구에게 일정 공유부터 시작한다.

## 제품 범위

대화·회의를 가져와 나의 일정과 할 일을 제안하고, 확인한 일정을 Google Calendar와 연결한다. 선택한 일정은 친구에게 링크로 공유하며 친구는 자신의 캘린더에 복사한다.

- 오늘: 시간순 일정, 시간이 없는 할 일, 확인이 필요한 AI 제안.
- 캘린더: 주간·월간 조회, 생성·수정·삭제, Google 동기화 상태.
- 기록: 카톡 원문·회의 전사문과 그 기록에서 생성한 일정의 연결.
- 비서: 현재 선택한 일정과 기록을 바탕으로 질문 및 수정 제안.
- 공유: 선택한 일정 미리보기, 내 Google 캘린더에 추가, 소유자의 링크 해제.

팀 공동 공간, 공동 편집, 공유 원본의 변경을 친구 캘린더에 자동 전파하는 기능은 첫 버전에 포함하지 않는다.

## 현재 구현과 제약

순수 JS·빌드 없음과 오프라인 파서를 유지한다. Gemini는 기존 서버 프록시를 사용하고 이용자에게 서비스 키 설정을 요구하지 않는다.

현재 google-calendar.js는 메모리에 보관한 Google 액세스 토큰으로 선택한 기간을 조회하고 일정을 순서대로 등록한다. 계정 저장, 토큰 갱신, 캘린더 수정·삭제, 페이지네이션, 등록 중 일부 실패 시 중복 방지는 아직 없다.

실서비스 OAuth에서 origin_mismatch가 관찰되었다. Google Cloud의 해당 웹 클라이언트에 https://dotodo-ten.vercel.app JavaScript origin 등록 후 실제 동의를 확인해야 한다. 설정 완료나 실제 연결 성공으로 간주하지 않는다.

## 저장과 인증 설계

계정 인증과 Google Calendar 권한 동의를 구분한다. 서버는 계정별 데이터 접근을 검사한다. 지속 동기화를 위한 Google 갱신 토큰은 서버에서 암호화해 보관하고 브라우저 저장소·응답·로그에 노출하지 않는다. 연결 해제 시 갱신 자격 증명을 폐기한다.

저장 대상:

- users: 내부 사용자 ID와 인증 제공자 계정 식별자.
- records: 소유자, 입력 종류, 원문 또는 저장 파일 참조, 처리 상태.
- events: 소유자, 제목, 시작·종료·시간대, 종일 여부, 장소, 출처, 버전.
- todos: 소유자, 연결 일정, 내용, 완료 여부, 선택적인 기한.
- calendar_links: 로컬 일정 ID, Google 계정·캘린더·이벤트 ID, 원격 버전, 동기화 상태.
- shares: 소유자, 추측 불가능한 토큰의 해시, 공유용 일정 스냅샷, 만료·해제 시각.
- share_imports: 수신자, 공유 ID, 공유 항목 ID, 등록 결과. 동일 항목 재등록 방지.

사용자가 기존 DB·로그인 서비스가 없음을 확인했다. 새 계정·DB·파일 저장 기반이 필요하다. 제공자는 운영 연결 단계에서 선정하고 유료 리소스를 임의로 생성하지 않는다. 제공자가 없는 동안에도 순수 함수·화면·API 계약은 개발할 수 있다.

## Google 일정 동기화 규칙

AI 추출 결과는 제안 상태로 저장한다. 사용자가 확인하면 Google에 등록한다. 애매한 날짜·담당자·시간 충돌은 확인을 요청한다.

성공한 등록은 즉시 원격 ID와 함께 저장한다. 요청 재시도는 동일한 작업 ID를 사용해 중복을 막는다. 일부 성공 후 실패한 경우 성공 항목을 다시 생성하지 않는다.

수정·삭제는 일정 상세 화면에서 명시적으로 실행한다. 삭제 전 Google에서도 삭제되는지 표시한다. 원격 버전이 바뀌었으면 새 값을 읽고 사용자의 수정과 충돌하는지 확인한다. 반복 일정은 첫 버전에서 단일 발생 항목 편집만 지원하며 전체 반복 수정으로 확장하지 않는다.

앱 진입·기간 이동·수동 새로고침에서 원격 변경을 반영한다. 백그라운드 동기화는 서버 저장과 갱신 토큰 설정이 끝난 뒤 추가한다. 동기화 전 데이터에 실시간이라는 표현을 쓰지 않는다.

## 공유 규칙

공유 생성 시 제목·시간·장소·선택한 체크리스트의 스냅샷만 저장한다. 단톡방 원문, 전사문, 발신자 명단, OAuth 정보는 포함하지 않는다. 생성 전에 공유될 내용을 보여 준다.

받는 사람은 로그인 없이 미리보기를 볼 수 있다. 자신의 캘린더에 등록할 때 Google 권한 동의를 거친다. 링크 해제 후 신규 조회·등록은 차단한다. 이미 친구 캘린더에 복사된 일정은 지워지지 않는다는 설명을 소유자에게 제공한다.

공유 페이지는 검색 색인을 막고 외부 리퍼러에 링크가 전달되지 않도록 한다. 공개 API에는 원본 기록 접근 기능이 없어야 한다.

## 입력과 디자인

카톡 첨부 옆에 내보내기 가이드를 제공한다. PC·iOS·Android를 구분하고 메뉴 명칭은 실제 버전을 확인한다. 기존 데모 버튼과 두 포맷 파서를 유지한다.

녹음은 대면 회의 마이크와 음성 파일 업로드부터 시작한다. 녹음 중 상태·시간·일시정지를 표시하고 전사문, 결정 사항, 담당자, 기한을 추출한다. 일정에서 발언 시점으로 돌아갈 수 있게 한다. 온라인 회의 상대방 음성 수집을 마이크 녹음 지원과 동일하게 표현하지 않는다.

Slack·Discord는 초기 붙여넣기를 지원하고, 이후 선택한 스레드·메시지를 앱으로 보내는 API 연동을 추가한다. 전체 대화 자동 수집은 별도 범위다.

데스크톱은 왼쪽 탐색, 가운데 타임라인·캘린더, 오른쪽 비서로 구성한다. 모바일 비서는 하단 패널을 사용한다. 밝은 바탕과 파란 강조색, 일관된 아이콘을 사용한다. Tiro·에이닷의 기록·비서 흐름을 참고하고 Jarvis의 표현은 상태 표시와 녹음 파형에 제한한다.

## 구현 순서와 완료 기준

1. Google 연결 검증 및 캘린더 관리: 페이지네이션, 조회·생성·수정·삭제, 만료·충돌·일부 실패를 테스트한다. 실제 쓰기 검증은 전용 테스트 일정으로만 한다.
2. 계정별 저장: 새 기기에서 동일 계정 일정 복원, 타 계정 데이터 접근 차단, 연결 해제를 검증한다.
3. 카톡 가이드: 기기별 안내와 첨부 복귀, PC·모바일 파서 회귀를 확인한다.
4. 공유: 로그인 전 미리보기, 다른 계정의 등록, 중복 클릭, 해제·만료, 원문 비노출을 검증한다.
5. 녹음: 권한 거절·중단·파일 업로드·전사 실패 복구, 전사와 추출 근거 연결을 검증한다.
6. Slack·Discord: 제공자별 설치 권한과 API 제한을 반영한 별도 구현 계획을 작성한다.

기능별 main 직접 커밋, PR 없음. 기존 node 테스트와 모의 API 브라우저 테스트를 유지한다. 실제 개인 대화·녹음의 외부 AI 전송 검증에는 해당 데이터 전송 권한을 확인한다.
